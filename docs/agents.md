# Role agents and prompts — daily use

> The three role agents this repo uses to run Trellis work, and the three prompt
> shortcuts that drive a session. Both sets are **generated by the `trellis`
> CLI**: they live in `.pi/agents/` and `.pi/prompts/`, which this repository
> does not track, and `trellis update` owns them — editing them here is a
> local-only change that the next update discards. The workflow they implement is
> [`.trellis/workflow.md`](../.trellis/workflow.md).
>
> Entry contract and heading convention: [`docs/README.md`](./README.md).

---

### `trellis-implement`

**What it is.** The implementation agent: it reads the active task's `implement.jsonl`, `prd.md`, `design.md`, and `implement.md`, then makes the change using existing project patterns and runs the focused checks it can.

**Reach for it when.** A task is `in_progress` and code needs writing. The main session dispatches it rather than editing inline, so the implementation gets its own context.

**Invoke.** `subagent({ agent: "trellis-implement", task: "..." })`. Its toolset is `read, write, edit, bash, find, grep` — it cannot commit.

**Config.** None — an ignored file under `.pi/agents/`, regenerated by `trellis update`.

### `trellis-check`

**What it is.** The review agent: it inspects the diff against the task artifacts and the project specs, fixes in-scope issues directly, and runs the quality gates for the touched code.

**Reach for it when.** Implementation is done and the change needs an independent pass before spec updates and the commit. It is the review gate the workflow calls for after each implementation step.

**Invoke.** `subagent({ agent: "trellis-check", task: "..." })`. Same toolset as `trellis-implement`.

**Config.** None — an ignored file under `.pi/agents/`.

### `trellis-research`

**What it is.** The research agent: it searches code, specs, and external documentation, and persists each distinct finding to a file under the task's `research/` directory so the result survives compaction and handoff.

**Reach for it when.** A question needs looking up and the answer should end up in a file rather than a conversation — background reading, source verification, or scoping an unfamiliar area.

**Invoke.** `subagent({ agent: "trellis-research", task: "..." })`. It may only write under the task's `research/`, so it cannot touch code or specs.

**Config.** None — an ignored file under `.pi/agents/`.

### `/trellis-start`

**What it is.** The session bootstrap prompt: it loads the compact Trellis context (identity, git state, active task, journal location), the phase index, and the relevant guideline indexes, then decides the next action from the task's status.

**Reach for it when.** A fresh session on this repo, before any Trellis work.

**Invoke.** `/trellis-start` — the name Pi registers is the prompt filename stem `trellis-start`.

**Config.** None — an ignored file under `.pi/prompts/`.

### `/trellis-continue`

**What it is.** The resume prompt: it reads the active task's `status` and artifact presence and routes to the matching phase step, so you do not have to remember where the flow was.

**Reach for it when.** Returning to a task mid-flight — the status plus which artifacts exist (`planning` with only `prd.md`, `in_progress` with implementation done, and so on) decides where it resumes.

**Invoke.** `/trellis-continue` — the filename stem `trellis-continue`.

**Config.** None — an ignored file under `.pi/prompts/`.

### `/trellis-finish-work`

**What it is.** The wrap-up prompt: it archives the active task (and any other finished task you confirm) and records the session journal. It does **not** commit code — that happens earlier, in workflow Phase 3.4.

**Reach for it when.** Every acceptance criterion is met, the spec updates are written, and the work is committed.

**Invoke.** `/trellis-finish-work` — the filename stem `trellis-finish-work`.

**Config.** None — an ignored file under `.pi/prompts/`.

---

## A note on the prompt spelling

This page states the hyphen form because that is what the generated extension
registers: Pi names a project prompt after its filename stem, so
`.pi/prompts/trellis-continue.md` is reached as `/trellis-continue`. Two tracked
documents — [`AGENTS.md`](../AGENTS.md) and
[`.trellis/workflow.md`](../.trellis/workflow.md) — spell the same commands
`/trellis:continue` and `/trellis:finish-work`. The confirming evidence and the
conflicting source are recorded in the task's `research/check-notes.md`.
