# Design — built-in MCP migration

## Decisions

| # | Decision | Rationale | Alternative rejected |
|---|---|---|---|
| **D1** | Do this as a Trellis task with `prd.md` + `design.md` + `implement.md` | ~13 tracked files across config, two scripts, `.gitignore`, and four spec files; the change inverts a documented invariant, so the reasoning must be reviewable before edits land | Inline edits + one commit (chosen for `ec4d473`, too small a frame for this) |
| **D2** | The server uses `exposure: "codemode"` | Pi's documented default, and the reason the adapter was kept around (context cost) is preserved: tools are callable from `codemode` scripts without being declared. `codemode` auto-activates when such a server connects, so no `defaultTools` entry is needed | `direct` (declares the full tool list on every request), `deferred` (needs `tool_search`; tools only reach the model after a search) |
| **D3** | Register only in `~/.pi/agent/mcp.json`; leave `~/.config/mcp/mcp.json` untouched | Pi reads only its own file, and the global file is shared with every other MCP-aware tool on this machine — it is not this repo's to rewrite or delete once the adapter is gone | Writing both files (two sources of truth to keep in sync); removing our global entry (silently breaks other tools) |
| **D4** | `~/.pi/agent/mcp.json` is **generated + ignored**, not symlinked into `pi-agent/` | Pi rewrites this file: `/mcp` saves exposure/enabled changes and `pi mcp add` appends servers. A symlink would route those writes into the git working tree — the same trap the spec already records for `auto-compact.json` and `pi-vcc-config.json` | Tracked file symlinked via `PI_FILES` (like `i-have-adhd.json`, which is read-only at runtime) |
| **D5** | The registration entry is `{ command, args: [], exposure: "codemode" }`; the adapter's `lifecycle: "lazy"` key goes | `lifecycle` is an adapter concept with no meaning to built-in MCP; `exposure` makes the D2 intent explicit in the file the user can inspect, instead of relying on an upstream default | Relying on Pi's implicit default and writing only `{ command, args: [] }`; adding a `--exposure` flag to the helper for a single call site |
| **D6** | `MCP_CFG` becomes `$HOME/.pi/agent/mcp.json` | It is a Pi harness path now. The "follow the reader, not XDG" rule existed only because the adapter hardcoded `~/.config/mcp/`; with built-in MCP the reader *is* Pi's config dir, so the rule and doctor's `XDG_CONFIG_HOME` warning both retire | Keeping `MCP_CFG` global and adding a second constant (`PI_MCP_CFG`) — two names for one destination |
| **D7** | `mcp.json` and `mcp.log*` join `PI_NOT_SYNCED` and `.gitignore` | `doctor.sh` fails when a reported-skipped path is not ignored, so the pairing is mandatory, not cosmetic. `mcp.log` is written by Pi's MCP extension (`docs/mcp.md`: appended per server logging notification, rotated to `mcp.log.1`) | Ignoring them without listing them (doctor reports an unpaired path) |
| **D8** | `docs/plugins.md` loses the `pi-mcp-adapter` section; the MCP story lives in `README.md` + spec | `check-docs.mjs` compares `docs/plugins.md` headings against core `packages[]`, so a section for a removed package fails the check. MCP is no longer a *plugin* of this repo — it is part of Pi — so the usage-layer home moves to the README section that already covers the server | Keeping the section and excluding it in `check-docs.mjs` (weakens the invariant the checker exists to enforce) |
| **D9** | The spec's "global MCP config" material is rewritten, not deleted | The global file still exists and still holds a (now unmanaged) entry. The spec must say who owns it now: the user and other MCP clients, not this repo | Deleting the section (loses the reason no path list holds it) |
| **D10** | Rollback = revert the commit and re-run `./setup.sh` | Every change is declarative or generated by a repo script. `~/.config/mcp/mcp.json` was never touched, the leftover `mcp-cache.json` is inert, and `pi-mcp-adapter` reinstalls from `packages[]` | Hand-restoring files from the `*.bak-*` backups |

## Boundaries

- **Pi owns** `~/.pi/agent/mcp.json`'s *runtime* edits (exposure toggles, `pi mcp add`).
  **The repo owns** its canonical content, written by `scripts/install-mcp.sh`.
  Divergence is reported by `doctor.sh` and repaired by re-running the installer —
  the same contract the global file had before.
- **The repo does not own** `~/.config/mcp/mcp.json` after this change. It is not in
  `PI_DIRS`, `PI_FILES`, or `PI_NOT_SYNCED`, and `sync.sh` must not report it. The
  entry there is now one of that file's foreign entries from this repo's point of
  view.
- **`codemode`** is the only path to server tools. It is activated by the MCP
  extension, not by `defaultTools`, so `settings.core.json` needs no `defaultTools`
  change.

## Data flow

```text
setup.sh
  └─ scripts/install-mcp.sh            # installs the binary if absent (upstream --skip-config)
       └─ scripts/register-mcp-server.mjs  "$MCP_CFG" codebase-memory-mcp codebase-memory-mcp
            └─ ~/.pi/agent/mcp.json    # mcpServers["codebase-memory-mcp"] = {command, args, exposure}
                 └─ Pi session start   # builtin:mcp connects enabled servers in the background
                      └─ codemode       # mcp__codebase_memory_mcp__* callable from scripts
```

`scripts/doctor.sh` reads the same `MCP_CFG` and calls the helper with `--check`,
so writer and verifier cannot drift apart. `scripts/lib.sh` stays the single
definition of the destination.

## Contracts

- **Entry shape** (writer and checker agree): `command` is the bare PATH-resolved
  name, `args` is `[]`, `exposure` is `"codemode"`. No machine-specific absolute
  path — the file stays portable and diffable.
- **Helper guards** (kept, with Pi as the stated reader): refuse on invalid JSON,
  a non-object root, a non-object `mcpServers`, and a file using `mcp-servers`
  instead of `mcpServers`. Pi reads the same camelCase key, so the shadowing
  hazard is unchanged.
- **Path lists**: `PI_DIRS`, `PI_FILES`, `PI_NOT_SYNCED`, `MCP_CFG` are declared
  only in `lib.sh`; no script re-declares them.
- **`.gitignore` pairing**: every `PI_NOT_SYNCED` file has an explicit
  `.gitignore` entry, enforced by `doctor.sh`.
- **Docs coverage**: `docs/plugins.md` headings == core `packages[]`.

## Compatibility and migration

- **Removed**: `npm:pi-mcp-adapter` from `packages[]` and the adapter's settings
  key from core.
- **Added**: `~/.pi/agent/mcp.json` (new file, generated on the next
  `install-mcp.sh` run).
- **Unchanged on disk**: `~/.config/mcp/mcp.json`, the installed binary, and
  `~/.pi/agent/mcp-cache.json` (now orphaned and inert: no extension reads it).
- **Lost capability, accepted**: the single `mcp` proxy tool, lazy connect, the
  schema cache, `/mcp setup`, `mcp install`, and `mcpScript` batching. Replaced
  by native per-tool registration with `codemode` exposure, `pi mcp` shell
  commands, `/mcp`'s panel, OAuth, and `mcp.log`.
- **Ordering**: Pi must pick up the new settings before `pi mcp list` proves
  anything, because the current session was started with the adapter loaded.
  Verification therefore happens in a fresh `pi mcp list` process, not in this
  session's tool list.
- **Session impact**: this session keeps its adapter-provided `mcp` gateway tool
  until restart; after the swap, MCP calls go through `codemode`.

## Risks

- **R-a (medium)** — A future `pi` update could change the built-in entry shape or
  the default exposure. Mitigation: `exposure` is written explicitly, and
  `doctor.sh` compares the file against the helper's own output, so a shape change
  fails loudly instead of silently.
- **R-b (low)** — `pi mcp list` fails on a shell whose `PATH` predates the
  upstream installer's profile line. Mitigation: the same PATH-tolerant fallback
  the installer already uses applies to the doctor check; the stored `command` is
  the bare name, so a Pi session resolves it in its own environment.
- **R-c (low)** — Editing exposure through `/mcp` creates drift from the repo
  copy. Mitigation: documented above as the intended contract; `doctor.sh` reports
  it and `./setup.sh` restores.
- **R-d (low)** — `check-docs.mjs` compares headings, so the section removal must
  keep the file's heading levels consistent with the remaining sections.

## Verification design

1. `node /tmp/mcp-warn-probe.mjs <cwd>` (already used in `ec4d473`): loads the real
   `builtInExtensions` through `DefaultResourceLoader` and prints the loaded
   extension list plus warnings. Expect `builtin:mcp` present, `warnings: []`.
2. `pi mcp list` in a fresh process: server state and tool names.
3. `scripts/render-settings.mjs … --check`, `scripts/doctor.sh`,
   `node scripts/check-docs.mjs`: the three mechanical invariants.
4. `git grep -n -E 'pi-mcp-adapter|mcp-cache|mcpScript|"lifecycle"'` over tracked
   files (AC6).
5. `./setup.sh` twice, checking the second run rewrites nothing (AC3, AC7).
